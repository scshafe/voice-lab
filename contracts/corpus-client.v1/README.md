# `corpus-client.v1` contract

What a capture client other than voice-lab-desktop needs to record into the PC's corpus: the
house panel (D-056, [docs/design/HOUSE-PANEL.md](../../docs/design/HOUSE-PANEL.md)). It is
shaped like lexinet's `study.v1`.

- [`openapi.json`](openapi.json) is the OpenAPI 3.1 authority for the routes a corpus client's
  token reaches. Its components and [`schemas/`](schemas) are the JSON Schemas of the
  contracts, generated from the code that enforces them.
- [`manifest.json`](manifest.json) names the required semantics and the examples, each with
  what it is expected to be (an invalid one with where and why the PC refuses it). It also binds
  every other file of the bundle by SHA-256 and size.
- [`PROTOCOL.md`](PROTOCOL.md) says how to use the routes: sign-in, the approval and ledger, the
  take package, the intake, decisions, retries, and the canonical form, byte for byte.
- [`examples/`](examples) holds the records with their exact bytes:
  - a golden take package (`examples/take/`), whose `original.wav` is given by an integer
    recipe (`original.wav.recipe.json`), since the repository holds no audio;
  - the D-021 records, a session request, a decision request, and the two refusals a corpus
    client meets;
  - the canonical-JSON vectors;
  - `invalid/`.

## Pinning

Pin the commit, `manifest.json`'s SHA-256 and the bundle digest: each file's path, in sorted
order, hashed as `path NUL contents NUL` into one SHA-256. No tags are needed. From a checkout:

```sh
python -m cole_voice_lab.contract_bundle digest
```

## The live check: the fixture server

A client's live check runs against the PC's own code, from a pinned checkout in a venv (the
API image's hash-locked closure):

```sh
python -m cole_voice_lab.contract_fixture serve --root "$(mktemp -d)" --report fixture.json
```

It serves on loopback until SIGINT or SIGTERM, keeps every file under `--root` (an empty
directory), and writes `fixture.json` once it is listening:

- `api_url`: the real API server, its staging, routes and the scoped verifier. After each
  finalize and each decision it runs the real validator, admission and publisher pass, so a
  session's outcome and a request's status are final by the time their call returns.
- `oidc`: the discovery document of a fake Pocket ID that behaves as v2.13.0 does. It approves a
  device code by itself after `--approve-after` pending polls (default 1), has no `slow_down`,
  refuses a `resource`, and revokes a refresh token's whole family when a rotated one is used
  again. Its RS256 key is made at start.
- `issuer`, `client_id` (`voice-lab-panel`), `subject`, `capture_profile` and `catalog` (the
  examples' catalog, which the fixture seeds).

Over plain HTTP the issuer is the nominal `https://id.fixture.invalid`; with `--tls-cert` and
`--tls-key` both servers use TLS and the issuer is the fake's own URL. `--admit-simulated`
admits a take whose evidence is `simulated`, which the PC refuses: it is the fixture's own
switch. `--port`, `--idp-port`, `--host` and `--interval` (the poll interval it announces)
are there for a test harness; `--once` binds, reports and exits.

## Compatibility

Compatibility is asymmetric:

- the PC may add optional fields to its answers within `corpus-client.v1`;
- requests and package records stay strict, and refuse unknown fields;
- a new required field, a new required semantic, or a changed meaning needs a new contract
  and a coordinated update of the client.

## How it is kept

Everything here but `README.md` and `PROTOCOL.md` is generated by
`python -m cole_voice_lab.contract_bundle write`. `scripts/verify` runs `check`, which fails
when any file differs from what the code would write now. An example therefore cannot drift
from the validator that judges a real take.

The examples are synthetic:

- no recording of Cole's;
- the array's USB product id is illustrative until the array has been measured;
- the catalog they name is the built-in `pilot-v2` suite as version 1 of `cole-corpus`, which
  `voice-lab catalog init --subject-id cole-self --from-builtin pilot-v2` publishes. A server
  seeded that way admits the golden take.
