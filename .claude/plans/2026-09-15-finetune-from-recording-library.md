# Plan: fine-tune from the recording library, programmatically

**Goal:** One lab command, `voice-lab finetune run`, selects the newest kept take of every spoken prompt straight from the recording library, builds the training set, fine-tunes F5-TTS v1 Base in a pinned runtime, writes listening samples and a run manifest, and can be re-run unchanged after every corpus revision.
**Out of scope:** A button inside the native app (Swift view + service command + rebuild; separate plan once this command exists). Lab packages, intake, dataset manifests, pilot gate, hosted training. Any model other than F5-TTS v1 Base. Hash-locking every training wheel (pin versions now, lock later).

## Context

- Cole's corpus model: the live corpus is the latest kept take per prompt; small continuous revisions; re-tune after each. Recording and training on the same M4 24 GB MacBook Air. Memory: `corpus-model-latest-per-prompt`, `outcome-over-pipeline`.
- Working prototype (2026-09-15, manual): selector `scratchpad/select_latest_34.py`, dataset builder `scratchpad/build_dataset.py`, and in `~/.local/share/cole-voice-lab/finetune-f5-01/` (call it F5): `run_finetune.py` (worker/W&B/light-checkpoint shim), `launch_full.sh` (hyperparameters), `synthesize.py`. 34 clips, 245.3 s, all sha256 verified. Full run launched with 120 epochs; 9 updates/epoch, ~4.6-8 s/update on MPS.
- Readers to reuse, never reimplement: `prompt_coverage.py:102-143` enumerates native heads (`RecordingTakeStore.iter_takes_for_projection`) and legacy rows (`legacy_projection_records`); legacy audio paths are in `LegacyProjectionRow.aliases` (`recording_discovery_contracts.py:117-123`); retained predicate `is_retained` (`recording_index.py:71`). Native audio = `take.seal.original_path`; a trim is `take.frame_range` (`recording_edits.py` is canonical for edit identity).
- Pinned F5 runtime `requirements/runtimes/f5-tts-1.1.22-mps.txt` has torch 2.6.0 and no training deps (accelerate, ema_pytorch, x_transformers, datasets, torchcodec 0.16). The verified training set is `F5/venv` (`pip freeze` it). Pretrained checkpoint: HF `SWivid/F5-TTS` revision `84e5a410d9cead4de2f847e7c9369a6440bdfaca`, `F5TTS_v1_Base/model_1250000.safetensors`, sha256 `670900fd14e6c458b95da6e9ed317cdb20dbaf7a1c02ac06a05475a9d32b6a38`, 1,348,435,761 bytes.
- F5-TTS quirks: `finetune_cli.py` reads the packed dataset from `<runtime site-packages>/../data/<name>_pinyin/` and writes checkpoints to `<runtime>/../ckpts/<name>/`; full checkpoints are 5.4 GB (model+optimizer+EMA), the shim's light checkpoints 2.7 GB. Disk is at 96 %.
- Conventions: `@canonical` docstring, `ContractModel` + canonical JSON, register contracts in `schema.py` and generate `schemas/*.schema.json` (`python -m cole_voice_lab.schema --check`), tests mirror module names, CLI wiring like `prompts coverage-report` (`cli.py:1627-1637`), model work out of process (D-004). Python only via `.venv/bin/python -I -B` with `PYTHONDONTWRITEBYTECODE=1`.
- Output root: `<asset-root>/derived/finetune/<run-id>/` (the recorder never scans `derived/`). Never write under `tmp/`, `raw/`, `provenance/`. The native app may be running against the same root: read-only access to takes, no locks taken. Do not touch the 1,000-take acceptance track or physical-test roots.
